FastH3: Attention Precision
and Kernel Evaluation

We compare NVIDIA cuDNN BF16, FastVideo Triton BF16, and FlashInfer CAKE Sage attention while keeping the original BF16 checkpoint, video decoder, conditioning inputs, prompts, and seeds fixed. CAKE Sage quantizes Q/K to INT8 and V to FP8. End-to-end generation, attention latency, and qualitative outputs are evaluated separately.

FastVideo uses its portable Triton block-sparse kernel on SM120, preserving logical tile128 routing through tile64 compute blocks. cuDNN uses its native SM120 tile128 CuTe DSL kernel. CAKE retains the same logical sparse selection and learned compression, while changing fine-attention arithmetic. Relative L2 is measured against cuDNN BF16. Full-VSA CAKE errors are 1.70%, 12.82%, and 13.48% at the three sampled step–layer pairs; numerical equivalence is not established. Operator speedups are distinct from end-to-end video speedups. Frame-aligned SSIM and PSNR are numerical comparisons, not perceptual quality scores.
FlashInfer CAKE implementation and experimental scope
The CAKE configuration invokes the SM120 CUDA kernel with an explicit backend="cake". Q/K INT8 and V FP8 quantization use the vLLM-Omni Triton adapters. An isolated evaluation launcher replaces only H3 fine-attention; production serving code is unchanged. First-warmup invocation evidence is recorded independently on all four ranks. This experiment evaluates CAKE Sage, not FlashInfer's BF16 CuTe kernel or the upstream dense sageattention.sageattn() entry point.
