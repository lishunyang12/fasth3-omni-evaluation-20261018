vLLM-Omni × ComfyUI

ComfyUI composes the workflow and sends requests to local or remote vLLM-Omni inference services. The service returns generated media to the graph. Official images illustrate the architecture and interface; their settings are not the benchmark configuration.

ComfyUI: available upstream

Verified against upstream main · 31 October 2026 · 08177216

The official extension connects a ComfyUI workflow to a local or remote vLLM-Omni service. Generation runs on the service; the client composes the workflow and handles inputs and outputs. Image, video, speech, music and multimodal nodes exist, but the selected model and API determine which inputs and operations work. Pinned official README · Current integration documentation

The H3 all-in-one workflow covers text-driven generation, first/last-frame conditioning and mixed references. It does not include a prompt-assistance LLM. A separate music-video workflow constructs shots from slices of an existing track and assembles them with the original audio. H3 all-in-one guide · H3 music-video guide

This is a source review, not a new inference test. The screenshot is the official UI example and does not specify the benchmark settings used earlier in this talk. The statement is pinned to main, not a promise that every item is in every released package.

Workflow explanations

Speaker notes for slide 15 (the former slide 14). Availability checked against upstream 08177216 on 31 October 2026; no new inference was run for this presentation update.

Text, keyframes and mixed references

Supported template. Start from a text prompt, constrain the first and/or last frame, or supply image, video and audio references. The connected inputs select T2VA, FL2VA or Ref2VA. These are alternative generation modes; the service must load the matching checkpoint partition. Official source

Timeline guides

Supported nodes and template. Place an image, video or audio guide at a chosen frame of the output. For example, frame 36 is 1.5 seconds at 24 FPS. This controls when supplied content appears. Requires base H3; the current guide path rejects FastH3, nonzero request LoRA and latent-mask editing. Official source

Inpainting and removal

Supported latent-mask template. Supply a source video and a spatial mask. Preserve the unmasked context and regenerate the selected region: remove an object or describe replacement content. A separate audio mask decides whether source audio is preserved or regenerated. Official source

Continuation and extension

Supported latent-mask template. Use a temporal mask to retain an initial part and regenerate the remaining interval, or request a longer duration to add new content after the source. This editing workflow is distinct from the rolling AV-tail implementation in our interactive demo. Official source

SeedVR2 upscale / restoration

Supported local and remote workflows. Generate an H3 clip, then restore or upscale its decoded frames with a separate SeedVR2 model. Preserve the generated audio and FPS. The local template uses a ComfyUI SeedVR2 extension; the remote route calls a separate vLLM-Omni SeedVR2 service. Official source

H3 second-pass refinement

Backend capability; server-configured. Generate a base latent, optionally upscale that latent, add noise and run the tail of the H3 denoising schedule before VAE decoding. This can change visual details and audio. It is request-mode only, rejects latent-tail continuation and latent-mask editing, and currently has no dedicated ComfyUI node or template. Official source

Music-driven video

Supported supplied-track template. Supply a music track and a character/style image. Slice the track, generate one Ref2VA shot per slice with locked source audio, then join the shots and restore the original recording as the final soundtrack. Shots share the reference image but do not carry latent history between requests; cuts are expected. Official source

ControlNet workflows

Draft PRs; not merged. Use pose, depth or edge hints to constrain motion and composition. The proposed workflow offers Canny, Depth, Pose, HED, MLSD and Inpaint controls. Dependencies and quality validation remain; do not present it as available on main. Official source

Character replacement

Open PR; not merged. Combine a source video and a new character reference to replace the subject while aiming to retain the original motion and scene. Backend dependencies and quality validation remain. Official source

Multi-anchor workflow

Open template PR; not merged. Combine an identity reference with several time-indexed image anchors in one ready-to-run graph. Reference and timeline-guide nodes already exist; the pending item is the combined template, not the entire guide capability. Official source

Long-form stories and avatars

RFC proposals. Compose multiple bounded shots or continuation segments into story, dialogue and repeatable-avatar workflows, with explicit boundary and audio handling. This is a proposed workflow family, not a promise of unlimited single-request generation or real-time performance. Official source

ComfyUI 每个工作流：输入、节点、机制与限制

中文逐项讲解：ComfyUI 负责组织素材、参数、节点和输出；H3 推理由 vLLM-Omni 服务执行。以下按 Slides 的工作流类别展开，共 11 项。基础功能、完整模板和提案的状态分别列明。

素材与提示词 → ComfyUI 节点编排 → vLLM-Omni 推理服务 → 视频/音频 → 组装、预览、保存
1. 文字、首尾帧与混合参考2. 时间轴引导3. 局部重绘与物体移除4. 片段续接与延长5. SeedVR2 超分与画质修复6. H3 二次采样7. 音乐驱动视频8. ControlNet 条件控制9. 角色替换10. 身份参考 + 多时刻锚点11. 长篇叙事、长视频与可重复数字人

1. 文字、首尾帧与混合参考：All-in-One / H3-06

已支持模板

输入：文字提示词；按模式选择首帧、尾帧，或人物图片、动作视频、声音参考。服务 URL、模型名、时长、seed 与采样参数由共享节点提供。

文字 / 首尾帧 / 参考素材 → Generate Video → Save Video
  1. T2VA：不连接 frame 或 references，以文字生成视频和同步音频。底层使用 FL2VA 分区。
  2. FL2VA：Load Image 接 first_frame、last_frame 或两者，约束开始/结束画面；文字描述中间动作。上一段末帧也可作为下一段首帧，但单帧本身不携带完整运动与音频历史。
  3. Ref2VA：素材接入 Video References，再接 Generate Video；提示词以 <Picture 1>、<Video 1>、<Audio 1> 指明各类参考用途。人物参考约束外观，动作参考提供动作线索，普通声音参考提供音色等条件。
  4. 返回的 VIDEO 包含生成画面和音轨，Save Video 保存 MP4。模板默认 124 帧 / 24 FPS，约 5.167 秒。

例子：只写“一个人在雨中奔跑”用 T2VA；给跑步前后两张构图用 FL2VA；指定人物长相、动作片段和声音风格用 Ref2VA。

使用边界：三个分支是可选路由；同时启用会分别发请求。frame 与 references 不混接。服务器必须加载对应分区，ComfyUI 切换连线不会自动加载缺失权重。模板没有内置提示词 LLM。

2. 时间轴引导：Timeline Guides

已支持节点和模板

输入：要在特定时间出现的图片、短视频或音频，以及每个素材的 frame_index。

Load Image / Video / Audio → Add Guide × N → Generate Video.timeline_guides → Save Video
  1. 每个 MiniMax H3 Add Guide 节点增加一条时间引导，串联后送入 timeline_guides。24 FPS 下 frame_index=36 对应 1.5 秒，72 对应 3 秒；负数从片尾计算。
  2. 服务端把条件对齐到输出时间轴。普通 reference 表达“参考什么”，timeline guide 还表达“在什么时候参考”。引导不自动变成新的 <Picture N> 等语义参考标签。
  3. 视频 guide 默认只取画面；需要声音时，从 Get Video Components 取出 audio，再接同一个 guide 的 audio。
  4. 可单独使用 guide，也可按接口约束和首尾帧或 Ref2VA references 组合。请求会由服务端检查帧网格、区间和冲突。

例子：要求人物在 1.5 秒举杯、3 秒转向镜头，可分别放入对应构图作为锚点，引导中间过渡。

使用边界：当前路径要求 Base H3；拒绝 FastH3、非零 request LoRA（含 Turbo）及 latent-mask editing 等组合。最多 8 条 guide；不保证严格逐像素复现或任意冲突锚点都能自然连接。

3. 局部重绘与物体移除：WF-05 空间遮罩

已支持 latent-mask 模板

输入：原视频、选定编辑区域的遮罩、希望生成的内容描述；需要时单独设置音频遮罩。

Load Video + 空间 Mask + 提示词 → Latent Mask Editing → Generate Video → Save Video
  1. Mask Canvas、Mask Rectangle、Combine Masks 可以画矩形；任意形状可用 Load Image (as Mask)。先看 Mask Preview 的红色覆盖区域，确认编辑范围。
  2. 遮罩 0 表示保留，1 表示重新生成。服务端编码原视频，以 latent 遮罩决定哪些位置保留源内容、哪些位置进行生成。
  3. 物体移除：遮住待去掉的物体，提示词描述应补回的背景；局部重绘：遮住目标区域，描述新内容。
  4. 音频有独立开关：audio mask=0 保留源音频路径，=1 重生成全段声音。只改画面时，避免误开音频编辑。

例子：移除桌上的杯子，同时尽量保留人物、桌面边缘和相机运动。

使用边界：该模板使用 FL2VA 分区。保留约束在 latent 空间，VAE 编解码后不等于像素或文件字节完全相同；遮罩过小会留边缘，运动物体需要检查逐帧覆盖。预览遮罩不运行模型。

4. 片段续接与延长：WF-05 时间遮罩

已支持 latent-mask 模板

输入：原视频、目标时长和保留范围；continuation 模式还配置 preserve_fraction。

Load Video + Temporal Mask → Generate Video（目标时长）→ Save Video
  1. Continuation：保留原片开头的一部分，把后面的时间区域标成可重生成，让情节沿新提示词继续发展。
  2. Extension：目标时长超过原片，将追加时间区域留给模型生成。Temporal Mask 的时长应与 Generate Video 一致。
  3. 源视频在 latent 空间提供保留区域的约束，音频保留/重生成由独立音频遮罩决定。
  4. 输出是一段按目标时长编辑的完整片段，保存后检查保留边界、动作连续性和声音。

例子：保留人物走入房间的开头，再生成坐下说话的后半段；或把已有短片向后延长。

使用边界：这条 FL2VA latent-mask 路线与第 11 页自定义 Ref2VA rolling demo 不同。demo 逐轮携带 AV 尾部、生成 124 帧再裁 5 帧；时间遮罩模板不能直接解释为同一套 20% 噪声 / prefix off 配置。

5. SeedVR2 超分与画质修复：WF-07

已支持本地和远端路径

输入：H3 生成的视频，或已有视频；SeedVR2 模型、输出短边/目标尺寸、批量和显存相关参数。

H3 VIDEO → 拆出 frames / audio / FPS → SeedVR2(frames) → Create Video + 原音轨 → Save Video
  1. 先让 H3 完成视频和音频生成，再把已解码的图像帧送给独立的 SeedVR2 修复模型。
  2. 原 WF-07 本地路径在 ComfyUI 侧加载 SeedVR2；远端路径调用单独的 vLLM-Omni SeedVR2 服务。H3 与 SeedVR2 的服务地址和模型可以不同。
  3. 模板示例把 1344×768 的短边设为 1536，输出约为 2688×1536；resolution 指目标短边，不是固定的 2 倍系数。
  4. 修复后的帧重新组成视频，接回原来的 FPS 和音轨。比较原片与修复片时同时检查细节、颜色和时间一致性。

例子：生成阶段先控制成本，最后把确定采用的镜头做高分辨率交付。

使用边界：SeedVR2 是额外模型，会增加算力、显存和耗时，也可能重建出与原片不同的细节。此处处理已解码帧，不是给 H3 历史条件加入 20% 噪声。

6. H3 二次采样：latent refinement

后端已支持；由服务端配置

输入：首轮 H3 结果 latent、latent_refine 强度，以及可选的 latent_upscale 目标尺寸。

H3 首轮 latent → 可选 latent upscale → 重新加噪 → H3 去噪日程尾段 → VAE 解码
  1. 先在较小画布生成，再按需要放大 latent；随后重新加噪，从选定日程位置继续调用 H3 DiT。也可不放大，仅在原尺寸细化。
  2. 例如首轮 50 步、latent_refine=0.4，二次运行日程尾部约 20 步。这个 0.4 是请求步数的比例，不等于前文历史条件的 20% 混合系数。
  3. 放大 latent 只提供初始结构；二次去噪使模型能重新生成目标尺寸下的细节。强度越大，允许的内容变化通常越大。
  4. 音频也会重新加噪并参与细化，因此需要重新听取输出。FL2VA 首尾帧在放大后按目标尺寸重新编码。

例子：先生成构图满意的低分辨率镜头，再用少量高分辨率步骤补充细节。

使用边界：目前没有独立 ComfyUI 节点或模板，可由服务器默认配置启用。该路径只支持 request mode，并与 latent-tail continuation、latent-mask editing 等组合存在限制；可学习 latent upscaler 还需要额外权重。更高强度不保证更清晰。

7. 音乐驱动视频：H3-03 已有音轨分支

已支持 supplied-track 模板

输入：完整音乐、统一的人物/风格图片、每个镜头的提示词，以及镜头时长。

Load Audio → 按镜头 Trim Audio → Ref2VA(lock_source) × N → Concatenate Video + 完整原音轨
  1. 按 124 帧 / 24 FPS 把歌曲划成约 5.167 秒的片段。三镜头的音频起点约为 0、5.17、10.33 秒，成片为 15.5 秒。
  2. 每个镜头独立调用 Ref2VA：共享图片进入 Video References，当前音频切片作为 driving audio；H3 Video Params 设 audio_mode=lock_source。
  3. 服务端把该段音频编码到目标音频 latent 并保持固定，使画面生成能利用已知的声音时间线。它不同于仅用 <Audio 1> 指定声音风格。
  4. Concatenate Video 拼接镜头，complete_audio 接整段原始录音。这样避免逐段音频 VAE 重建造成的接缝差异；导出的 MP4 音频仍可能有容器/编码转换，不能声称字节完全一致。

例子：一首歌的前三段分别用近景演唱、全身动作、舞台远景呈现，人物参考相同。

使用边界：镜头之间没有 latent 历史接力，允许剪辑切换；不保证连续相机运动或严格卡点。lock_source 要求恰好一条驱动音频，并且不会额外生成叠加音效。YuE2 自动生成音乐分支仍依赖对应服务和节点。

8. ControlNet 条件控制：WF-06

草稿 PR；未合并

输入：结构提示视频、提示词、控制类型与 strength；局部控制时还可涉及源视频和遮罩。

原视频 → 提取结构提示 → MiniMax-H3 Control → Generate Video → Save Video
  1. Pose 用骨架描述动作；Depth 用深度描述空间布局；Canny/HED 用边缘描述轮廓；MLSD 偏向直线结构；Inpaint 结合待修改区域。
  2. 预处理阶段把输入转换为所需提示图，ComfyUI 发送准备好的素材，服务端运行带相应 ControlNet/Union 权重的 H3。
  3. strength 控制结构条件的作用强度。文字描述生成外观，控制提示约束姿态、布局或轮廓；两者冲突时需要调整。

例子：沿用舞者的动作骨架，改变服装或场景；沿用建筑边缘布局生成新的视觉风格。

使用边界：当前相关前端 PR 为 draft。已有部分运行记录，但并非所有控制模式都通过最终画质验收。骨架漏检、方向错误、音频质量及不支持的组合仍需检查，不能把“请求能运行”写成质量已完成验证。

9. 角色替换：H3-04

开放 PR；未合并

输入：提供动作、镜头和场景的原视频，以及一个或多个目标人物参考图。

原视频 + 新角色图片 + 身份映射提示词 → Ref2VA / 适配器 → 输出替换视频
  1. 单人：<Video 1> 提供源视频，<Picture 1> 提供目标角色；提示词明确希望替换谁、保留哪些动作与场景。

10. 身份参考 + 多时刻锚点：WF-04

组合模板 PR 未合并；基础节点已存在

输入：一张人物身份参考，以及分别指定 1.5 秒、3 秒、5 秒画面的三张时间锚点。

11. 长篇叙事、长视频与可重复数字人：H3-01 / 02 / 05

完整制作模板属于 RFC 提案

输入：分镜或回复文本、人物与场景参考、音频策略、每段时长以及段间接续策略。

剧本 / 对话 → 分镜与参考 → 分段生成或续接 → 检查边界与音轨 → 保存、拼接、继续
  1. H3-01 文戏/叙事：逐镜头编写动作、对白与相机要求，共享必要的人物/场景参考，最后保留音频完成组装。
  2. H3-02 长视频：生成有界片段，明确重叠多少、保留哪段、裁掉哪段，处理 AV 时间轴和段间接缝。
  3. H3-05 数字人：重复生成同一角色的说话/倾听片段，结合输入、回复、音频对齐、片段持久化与恢复机制，组成可持续运行的应用。

例子：对话短剧使用多镜头剪辑；数字人使用连续回复片段。两者对无缝动作、身份和音频的要求不同。

使用边界：“无限”表示可以重复请求，不表示单次推理无限长、永不漂移或必然实时。FL2VA 末帧接首帧、latent-mask 续接和 Ref2VA AV-tail 都应按任务比较，不能混称为同一种接续。
