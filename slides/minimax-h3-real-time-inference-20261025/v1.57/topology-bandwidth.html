Compute-rich, bandwidth-modest: choose the payload route

Hardware insight · Route diagram · Communication optimizations

Which path?

The diagram preserves two CPU sockets, four PCIe subtrees, eight GPUs and four ConnectX-8 cards. Arrows show one cross-socket example, GPU 0 → GPU 4. They are a logical data-flow illustration, not a packet trace.

Original application code, controlled local-only NCCL replay: same-subtree pairs use P2P/CUMEM. The other six peers per rank use SHM/direct/direct, involving host buffers and shared CPU-facing PCIe uplinks; cross-NUMA traffic also uses the CPU interconnect. The audit found 8 directed P2P pairs and 48 SHM pairs. A host-buffer route must not be labeled direct GPU P2P.

Tested GPU-affine FlashInfer RDMA: GPU 0 → local PCIe subtree → its assigned CX8 port (mlx5_2) → RoCE fabric → destination CX8 port (mlx5_6) → local PCIe subtree → GPU 4. Payload bypasses the host-memory staging path and CPU uplinks; CPU control work still exists. External physical switch wiring was not audited.

Effective TX bandwidth equals off-rank bytes per GPU divided by this measured duration. It includes layout, allocations/input staging and synchronization. It excludes attention, GEMM and full H3 inference. The implementation comparison is not an isolated link-bandwidth experiment.

Scope of “original NCCL”

The replay uses unchanged, AST-extracted vLLM-Omni all_to_all_4D from commit 63487a7f22db603adefcdac378cfe2a26f6bcb7c. It explicitly adds NCCL_NET_DISABLE_INTRA=1 and NCCL_IB_DISABLE=1 with P2P and SHM enabled. The historical Base50 launch did not record that extra local-only control; its per-pair routes are unknown. An IB-disable-only replay selected NET/Socket across NUMA. Therefore the slide identifies the controlled replay and does not claim to reconstruct the historical Base50 packet path. NCCL itself supports RDMA.

Nominal capacity versus measured throughput

GPU/host Gen5 ×16: 64 GB/s raw one way (63.015 after 128b/130b encoding, before packets). Shared NIC Gen6 ×16: 128 GB/s raw. One 400 Gb/s port: 50 GB/s. Thin background/green physical-link widths use 0.05 pt per GB/s; black dashed arrows emphasize the logical SHM route rather than measured bandwidth. CPU-to-CPU bandwidth is 128 GB/s, as supplied by the presenter; the gray CPU link is drawn at 6.4 pt. This is a system bandwidth annotation, not a new measured payload result. The supplied value does not specify one-way versus aggregate-duplex accounting. Logical fabric connectivity is outside the physical-link width scale. Two ports share one NIC PCIe endpoint. These nominal rates are not achieved application throughput.

“Compute-rich, bandwidth-modest” describes inter-GPU communication relative to on-card Blackwell tensor compute. It is not a measured roofline claim or an assertion that every H3 operator is bandwidth-bound. Official RTX PRO 5000 capabilities.
