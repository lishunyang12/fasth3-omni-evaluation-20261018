在时间线上定位

fasth3.client.engine_generate 是客户端完整请求；8 个 worker 的 fasth3.request 对齐在同一个时间轴。

fasth3.dit.step_01…08、fasth3.block.00…49 标记步和层；fasth3.hsdp.pre.* / post.* 标记权重准备及释放；fasth3.attention.vsa、fasth3.mlp、fasth3.linear.* 标记 attention、MLP 和投影。VAE 与 MP4 导出也有独立标记。

NVTX 为 CPU 侧范围，应结合 CUDA API 关联与 GPU kernel 时间线分析。包含关系和异步重叠意味着这些时长不能直接相加，也不能把整个 HSDP hook 范围视为纯通信开销。

配置与解释边界

1344 × 768，124 帧，24 fps，seed 43；TP1 / USP8 / TE-TP8；8 次 PDD forward；FI BF16 attention；原生 VAE 8 卡并行；无 CPU offload。只改变 HSDP shard / replicate mesh。

采集 CUDA、NVTX 和 OS runtime；未采集 GPU 硬件计数器或 CPU sampling。trace 两端含少量等待和输出检查，应以请求标记定位。

Nsight 提示可能未收齐所有底层事件，以及未采集线程调度信息。8 卡请求、step、block 和 HSDP hook 的指定覆盖检查通过；这不表示每一个底层事件都无遗漏。完整诊断保留在 JSON 中。
