C6b native128 split-KV validation

Accepted explicit num_splits=2/4/8/16 on direct and mask APIs. Default1 and existing FastVideo environment route remain unsplit.
BF16 Q/K/V and P; FP32 accumulation, partial output and lnLSE; stable weighted merge; one final BF16 rounding. Physical128 tiles and logical selections preserved.
No lower precision, FI runtime dependency, or shape-only automatic dispatch was added.

Validation:
- 180 configurations =45 adversarial cases x splits2/4/8/16; zero failures. FP64 references for first26 cases, FP32 for larger cases.
- Reversed valid indices / poisoned unused capacity / deterministic repeats on26 cases x4 splits. FP32 scratch initialized to NaN and checked fully overwritten on all180 configurations.
- Oracle covers all rows for Sq<=2048; for larger inputs it samples boundary rows of every128 block plus256 random rows. Scratch initialization and default-vs-C5 equality checks cover full tensors.
- Large logits, cancellation, constant V, outliers, zero Q, all-zero sizes, empty rows and empty splits, ragged sizes0/1/17/63/64/65/127/128, odd counts, asymmetric lengths, B2, H1..56, aligned offsets and strides.
- 31 unseen held-out input cases, seed99017, splits2 and8, both prepared and metadata-inclusive calls. All independent FP32 gates pass.
- 11 representative held-out cases repeated in a fresh process and randomized order; no code changes after holdout began.
-45 pytest tests pass, including fullgraph compile, changing all graph inputs/metadata, concurrent graphs, alternate current device, invalid options and preallocated outputs.
-memcheck/racecheck/synccheck/initcheck:15 tests each, exit0 and no reported errors. Initcheck covers empty-allocated FP32 scratch and final outputs on the split path; the older unsplit BF16 TMA-store tracking limitation is not reclassified.
-23 prior default-path performance cases: output and LSE bitwise equal to frozen C5.
-pre-commit passed; kernel paths are deliberately excluded by repository configuration. git diff --check passed.

Maximum max_abs across adversarial split configurations: 0.01410150528
Maximum relative_l2 across adversarial split configurations: 0.002216225813
Maximum lse_max_abs across adversarial split configurations: 6.908106431e-05
Output gates unchanged: atol=.01,rtol=.01 and relativeL2<=.005; LSE atol=.002,rtol=.0002; exact empty0/-inf. A max absolute error above.01 can pass the relative tolerance; no thresholds were loosened.

NCU / KDA evidence:
-profile/native128-c6-baseline explains original utilization denominators and the96-CTA, two-long-row tail. H1 prefix SM busy13.793%, BF16 dense SoL10.854%; actual DRAM-byte utilization1.420%, distinct from aggregate DRAM throughput1.527%.
-profile/native128-c6-candidate archives the initial direct-global-store prototype and its255-register spilling bottleneck.
-profile/native128-c6b-candidate contains final full+PM+source captures and six-dimension analysis. Shared output staging reduces registers to236 and eliminates all measured local load/store spill instructions. H1 prefix producer busy72.77%, dense SoL31.39%, same11.073GFLOP.
-Producer-only SoL does not include merge; this is not a claim of near-peak overall performance. NCU separately cold-replays merge, so do not add those durations and call it hot application latency.
-Split8 TMA bytes grow89.65MB->111.67MB because Q is loaded for every split; K/V traffic is unchanged. Scratch50.72MB in this input. No DRAM/TMA equivalence is assumed.

Artifact integrity / limitations:
-Frozen final source outputs/c6_frozen; final-source-manifest.json covers production code, tests and docs. The holdout was not used to retune the implementation.
-tuning-epilogue.json has old-provider rebinding after the first case; exclude its old/new comparisons. tuning-epilogue-corrected.json is the valid paired comparison.
-The tests use synthetic selections/values. No full FastH3 checkpoint activations, end-to-end video quality, or vLLM-Omni inference parity claim is made.
-No commit, push or deployment was performed.
