Attention layout fusion removes 12 kernels per replay

At the retained 960 × 544 attention geometry, both 2-head and 3-head graphs execute 66 kernels in the original implementation and 54 after direct input/output fusion. This is an 18.2% reduction in kernel count, not an 18.2% latency claim.

What changed

The direct input kernel reads peer-major Q/K/V receive storage and writes tile-major buffers with exact padding. The direct output kernel combines transpose, untile, padding and owner-tail packing. FP4 attention, pooling, routing and coarse GEMM arithmetic are retained.

Where time remains

In the direct-input/output ranges, the native FP4 attention kernel accounts for 2 heads: 80.6%; 3 heads: 82.1% of summed kernel duration. Remaining layout work includes one receive-to-tile kernel and one output packing kernel. This trace does not measure the first-input or final-output RDMA waits in the eight-GPU pipeline.

Configuration and scope

Physical GPU 6, SM120; inference mode; BF16 QKV storage; retained native FP4 attention; tile size 128; VSA sparsity 0.9; reference keep rate 0.1; seed 43. There are 22,049 valid rows, 22,080 aligned rows and 29,056 tiled rows. Local rows: 2,760; head dimension: 128. The buffers represent the original eight-peer layout, but no communication runs in this test.

The full target remains 124 frames at 24 FPS (5.166667 s), 960 × 544, eight model evaluations and 2/3/2 bands. This component profile exercises the two distinct head counts, not a full three-band distributed pipeline. Its equivalence claim is relative to the already quantized reference, not the original BF16 model.

Capture limits and retained warnings

Collection starts after graph warm-up and stops after six NVTX ranges. Each range contains graph submissions and a final device synchronization. Occupancy checks run outside the ranges. Nsight reports possible incomplete CUDA/NVTX collection for the bounded capture and no-event warnings for guard subprocesses. All six ranges, 120 graph launches, and equal replay counts for each captured graph node were verified. These checks do not establish completeness of all possible events. Warnings are retained in the raw report and JSON.
